# Developer Guide — Echelon Routine Builder & Timer

A practical map of the codebase for anyone maintaining this app. For the deepest
detail, read the comments **inside `index.html`** — this file is the high-level orientation.

---

## 1. What it is
A **single-file web app** (`index.html`) for building, timing, and running
fitness classes. No framework, no build step, no server, no external libraries —
plain HTML/CSS/JavaScript. It runs by opening the file or from a web link, and
works offline.

**Do not add a build step or dependencies** unless you really mean to. The whole
value is that one file you can open anywhere.

## 3. How `index.html` is organized
Open it and you'll find, top to bottom:
1. **`<head>`** — page meta + Add-to-Home-Screen tags.
2. **`<style>`** — all CSS. Colors are **CSS variables** ("tokens") defined once in
   `:root` (dark theme) and `html[data-theme="light"]` (light theme). Re-brand by
   editing those tokens — components don't hardcode colors. See the theming note
   at the top of `<style>`.
3. **`<body>`** — the markup. The UI is several full-screen **views** (library,
   builder, catalog, plans, plan editor) plus **overlays** (run timer, settings &
   export dialogs). Only one view is visible at a time (others have `.hidden`).
   Most lists/rows are generated by JS, so the markup is mostly empty containers.
4. **`<script>`** — all logic, in one IIFE. Read the big **ARCHITECTURE** comment
   at the top of the script first.

### The core pattern
`state → render → events → state`
- **`state`** is the single source of truth (see the data model below). It lives in
  memory and is mirrored to `localStorage`.
- **`render*()`** functions read `state` and rebuild the DOM.
- **Event handlers** (the "Events" section) mutate `state`, then save + re-render.
- **`save()`** writes everything to `localStorage`. Most edits call
  `markDirty()`/`markPlanDirty()` which **debounce** the save (so typing isn't
  written on every keystroke); leaving a screen flushes immediately.
- **`loadState()` / `normalizeState()`** run once at startup and **repair/upgrade**
  saved data (fill missing fields, drop junk, migrate old values). This is why old
  saves keep working after an update.

## 4. The data model
Saved as JSON under the `localStorage` key **`tempo.v1`**:
```js
state = {
  settings:  { studioName, mode, theme, beeps, autostart,
               loadLabel, accent, logo, logoCustom },
  routines:  [ { id, name, description, tags:[], createdAt, updatedAt,
                 blocks:[ { id, name, exercises:[
                   { id, name, spring, side, duration, rest, reps } ] } ] } ],
  catalog:   [ exercise-shaped templates the user reuses ],
  sequences: [ { id, name, routineIds:[] } ]   // "class plans"
}
```
- `duration` = work seconds, `rest` = rest seconds after the exercise,
  `side` = `"L"`/`"R"`/`"both"`/`""`, `spring` = the load value (free text).
- **Data is per-device** (in the browser). It is NOT synced between people/devices.
  Settings → Backup/Restore moves it as a JSON file. A shared/synced library would
  need a backend (not present today).

## 5. Run locally
- **Simplest:** double-click `index.html` (opens in your browser).
- **With a local server** (needed if a browser blocks `file://` features):
  ```bash
  cd <this folder>
  python3 -m http.server 8000
  # open http://localhost:8000
  ```
There is **no build/compile** — edit the file, refresh the browser.

> Tip: edits are saved per-browser in `localStorage`. To test a clean install,
> open a private window or run `localStorage.clear()` in the dev console.

## 6. How to make common changes
| Want to change… | Edit… |
|---|---|
| Brand colors / theme | `:root` and `html[data-theme="light"]` token blocks in `<style>` |
| Default brand name / built-in logo | `defaultSettings()` and the `ECHELON_LOGO` constant in `<script>` |
| Wording / field labels | the `build*` functions and the markup |
| Add a setting | `defaultSettings()`, `normalizeState()`, the Settings modal markup, `openSettings()`, `saveSettings()` |
| Timer behavior | the "Run mode" section (`buildSteps`, `beginRun`, `tick`, `advanceStep`, …) |
| Exports (PDF / CSV / text) | `exportPDF` / `exportCSV` / `buildText` |
| Add a button/control | add it in the markup with an `id`, then wire it in the **Events** section |

## 7. Testing checklist (manual)
There are no automated tests; verify in a browser:
- Open the dev console — there should be **no errors**.
- Build a routine (blocks, exercises, time/rest/side/load), confirm totals update.
- Run it: countdown, auto-advance, Prev/Skip/Restart, the rest steps, completion.
- Export each format (PDF/CSV/text) and confirm the contents.
- Toggle **light/dark** (◐) and check both look right.
- Backup, then Restore the file; confirm data round-trips.
- Resize narrow (phone width) — the builder and top bar should adapt.

## 8. Deploy / publish updates
The live site is hosted on **GitHub Pages** from this repo
(`JustinTechGuyAtWork/echelon-timer`), served at
**https://justintechguyatwork.github.io/echelon-timer/**.

To publish a change:
```bash
# from a clone of this repo, after editing index.html
git add -A
git commit -m "describe the change"
git push
```
GitHub Pages rebuilds automatically (about a minute); everyone gets the new
version on their next open. The files served are exactly the ones in this repo,
so test locally first.

> The home-screen icons/manifest must stay alongside `index.html` for "Add to
> Home Screen" to use the Echelon icon.

## 9. Conventions & gotchas
- **Vanilla JS, ES5-ish style** (`var`, no modules). Keep it dependency-free.
- Build UI with the `el()` helper and set text via `textContent` (not `innerHTML`)
  to avoid HTML injection. Where HTML strings are built (PDF export), values go
  through `escapeHtml()`; CSV values go through `csv()` (which also blocks
  spreadsheet formula injection).
- Everything is keyed by a generated `id` (`uid()`); look records up with
  `findRoutine` / `findBlock` / `findSequence`.
- Accessibility is wired in (focus management on overlays, `aria-*`, a screen-reader
  live region, keyboard handlers) — keep new controls consistent with that.
- **Can't be done in this single-file app:** native Apple Watch control and
  cross-device cloud sync (those need native apps / a backend).
